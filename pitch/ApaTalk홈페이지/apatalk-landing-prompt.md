# 아파톡 회사 홈페이지 — 재현 프롬프트

`apatalk-toss-landing.html`을 처음부터 다시 만들기 위한 프롬프트입니다.
아래 `---` 아래 전체를 새 세션에 그대로 붙여 넣으면 같은 결과물이 나옵니다.

---

## 과제

아파트·오피스텔 입주민용 AI 생활 도우미 **아파톡(ApaTalk)** 의 회사 소개 랜딩 페이지를
**단일 HTML 파일 하나**로 만들어 주세요. 파일명은 `apatalk-toss-landing.html`.

- 외부 의존성은 웹폰트 CSS 2개(Pretendard Variable, Wanted Sans Variable CDN)만.
  프레임워크·빌드·번들러·아이콘 라이브러리 없음. CSS와 JS는 파일 안에 인라인.
- 언어는 한국어(`<html lang="ko">`), 모바일까지 반응형.
- 페이지 안에 **실제로 동작하는 프로토타입**이 들어갑니다. 스크린샷·목업 이미지가 아니라
  탭 이동·채팅·신청 폼이 클릭으로 작동하는 인터랙티브 UI여야 합니다.

## 디자인 방향

토스(toss.im)의 **레이아웃 문법만** 차용합니다: 흰 지면, 초대형 국문 헤드라인,
한 화면 한 메시지, 단일 액센트, 감쇠된 스크롤 모션. **파랑·초록은 쓰지 않습니다.**
색은 **로즈골드**입니다. 금속성 로즈골드 인상은 로즈 단색이 아니라
**로즈 + 샴페인 골드 조합**에서 나옵니다.

### 색 토큰 (전부 `oklch()`, raw hex 금지)

```css
:root{
  --bg:oklch(0.995 0.003 22);        /* 웜 오프화이트 지면 */
  --surface:oklch(0.962 0.009 22);   /* 교차 섹션, 아이콘 타일 */
  --surface-2:oklch(0.981 0.005 22); /* 카드 내부 입력 필드 */
  --cream:oklch(0.963 0.022 72);     /* 샴페인 골드 — 히어로 형태 1개 전용 */
  --fg:oklch(0.265 0.024 20);        /* 헤드라인·본문 */
  --fg-2:oklch(0.458 0.022 20);      /* 보조 본문, 모노라인 아이콘 */
  --muted:oklch(0.538 0.017 20);     /* 캡션, 비활성 */
  --border:oklch(0.923 0.011 22);    /* 1px 구분선 */
  --accent:oklch(0.60 0.098 12);     /* 로즈골드 — 면·아이콘·18px+ 텍스트 전용 */
  --accent-deep:oklch(0.435 0.095 8);/* 딥 로즈 — 솔리드 버튼, 작은 액센트 텍스트 */
  --accent-press:oklch(0.375 0.080 8);
  --accent-soft:oklch(0.955 0.030 12);/* 칩 배경 (hover oklch(0.918 0.046 12)) */
  --danger:oklch(0.485 0.205 27);    /* 폼 검증 — 액센트와 혼동되지 않게 채도 2배·명도 하향 */
  --ink:oklch(0.225 0.022 20);       /* 마감 CTA 섹션 */
  --ease:cubic-bezier(.16,1,.3,1);
  --ease-io:cubic-bezier(.4,0,.2,1);
}
```

지켜야 할 규칙:

1. **액센트 이원화.** `--accent` 위 흰 텍스트는 4.14:1이므로 아이콘·18px+ 텍스트까지만.
   솔리드 버튼과 작은 액센트 텍스트는 `--accent-deep`(흰 텍스트 8.3:1)을 씁니다.
   모든 전경/배경 조합이 4.5:1 이상이어야 하고, hover는 대비가 **올라가야** 합니다.
2. 로즈는 한 화면당 최대 2회. 마케팅 뷰포트에 솔리드 버튼은 단 하나.
3. 중립색은 순회색이 아니라 로즈 쪽으로 아주 미세하게(C ≈ 0.01) 편향 — 웜 지면 톤.
4. 히어로 유기 형태는 딱 2개(로즈 1 + 샴페인 골드 1), 정적으로, 900px 이하에서 축소·숨김.
5. 아이콘은 **1.7px 스트로크 모노라인 SVG + `currentColor`**, `<symbol>` 스프라이트 1개에 모아
   `<use href="#ic-...">`로 참조. **이모지 절대 금지.**

### 타입

- Display: `'Wanted Sans Variable'` — 헤드라인 전용. `font-weight:800`.
- Body: `'Pretendard Variable'` — 본문·UI. 기준 `17px / 450 / line-height 1.72`.
- 국문 디스플레이: `line-height:1.32`, `letter-spacing:0`. **국문에 음수 자간 금지.**
- 라틴 대문자 키커: `font-size:12px; font-weight:700; letter-spacing:.09em; text-transform:uppercase`.
- 모든 국문 블록에 `word-break:keep-all`.

## 섹션 구성 (순서 그대로)

1. **고정 내비** — `position:fixed`, 높이 64px, `backdrop-filter:blur(18px) saturate(1.6)`.
   스크롤 24px 넘으면 `.stuck`으로 하단 보더·배경 불투명도 상승. 좌측 로고(라운드 사각 마크 + `ApaTalk`),
   우측 텍스트 링크 + `프로토타입` 고스트 버튼.
2. **히어로** — 액센트 칩(펄스 점 + `아파트 · 오피스텔 입주민 전용 생활 도우미`),
   `clamp(30px,6.6vw,84px)` 2줄 헤드라인, 리드 1문장, 솔리드 CTA `프로토타입 만져보기` +
   보조 문구, `Scroll` 큐(1px 레일 안에서 막대가 흐르는 애니메이션).
   헤드라인은 `overflow:hidden` 줄 단위 마스크에서 올라오며 등장, 나머지는 `--d` 지연으로 순차 등장.
3. **스크롤 스토리** — `position:sticky` 화면 고정 + 3단계 카피 교차. 좌측 카피 / 우측 폰 목업.
   3단계: `01 질문 — 규정을 외우는 건 / 사람 몫이 아닙니다`,
   `02 연결 — 대화가 그대로 / 신청서가 됩니다`, `03 확인 — 접수 이후가 / 더 중요합니다`.
   각 단계에 태그 칩 3~4개, 상단에 진행 레일 3개. 폰 화면도 단계에 맞춰 홈 → 채팅 → 완료로 전환.
   **구현 규칙은 아래 "스크롤 스토리 정밀 규격" 참조 — 여기가 가장 까다롭습니다.**
4. **라이브 프로토타입** — `여기서 직접 / 만져보세요`. 실제 동작하는 폰 UI. 아래 "프로토타입 규격" 참조.
5. **기능 4개** — `관리사무소 업무를 / 줄이는 네 가지 축`: 근거 있는 답변 / 대화형 신청 / 세대 인증 /
   단계별 알림. 카드마다 모노라인 아이콘 + 제목 + 2문장.
6. **답변 해부** — `답변 하나에 / 세 가지가 들어갑니다`. 좌측에 번호 매긴 설명 3개(답변·근거·다음 행동),
   우측에 실제 답변 버블을 확대해 1·2·3 번호 배지를 붙인 카드.
7. **마감 CTA** — `--ink` 어두운 지면. `우리 건물에도 / 들여보시겠어요?` +
   도입 상담 폼(아파트·오피스텔 이름 / 담당자 이름 / 연락처). 빈 값·짧은 번호는 `--danger`로
   인라인 에러 표시, 통과하면 폼 자리를 완료 상태로 교체.
8. **푸터** — 로고 + 샘플 데이터 고지: "화면의 이름·세대·공지 내용은 동작 확인용 샘플입니다.
   실제 도입 시 해당 아파트·오피스텔의 규정 문서를 기준으로 학습합니다."

## 카피 규칙

- 지어낸 수치·지표·로고·고객사·후기를 **절대** 넣지 마세요. "3배 향상", "99% 만족" 같은 문장 금지.
- 마케팅 카피는 전부 **아파트 · 오피스텔** 로 일반화합니다. 특정 단지명을 쓰지 않습니다.
- 단, **프로토타입 화면 안에서만** 샘플 단지명 `골드아파트`를 씁니다(앱 헤더, 채팅 서브타이틀,
  관리사무소 표기, 학습 문서 목록 등). 제품 화면이라 구체적인 이름이 있는 게 자연스럽습니다.
- 규정 수치는 조항과 함께 제시합니다: "최대 4시간 — 주차 관리 규정 제8조 3항" 형태.
- 모든 편집 가능 영역에 `data-od-id="..."` 를 붙입니다(`hero-headline`, `feature-card-auth` 등).

## 스크롤 스토리 정밀 규격

`.story`는 `sticky` 뷰포트 + 그 아래 `height:360vh` 스페이서로 스크롤 진행률 `p`(0~1)를 만듭니다.
`p`는 `-story.getBoundingClientRect().top / (story.offsetHeight - innerHeight)`로 계산하고,
`requestAnimationFrame` 루프에서 `cur += (target - cur) * .13`로 감쇠, 차이가 `.0015` 미만이면 스냅.

**국문 텍스트 선명도가 이 섹션의 핵심 품질 기준입니다.** 다음을 반드시 지키세요.

- 스텝 불투명도는 삼각형 램프(`1 - |p-c|/w`)로 만들지 마세요. 중심점 한 곳에서만 1에 도달해
  스크롤 대부분 구간에서 스텝 두 개가 반투명하게 겹쳐 보이고, 읽히기 전에 지나갑니다.
- 대신 **평탄 구간**을 둡니다: 중심 `CENTERS=[.15,.5,.85]`, 완전 불투명 반폭 `HOLD=.13`,
  교차 페이드 폭 `FADE=.055`. 첫 스텝은 섹션 시작까지, 마지막 스텝은 섹션 끝까지 불투명 유지.
- **선명 구간(opacity 1)에서는 인라인 `opacity`·`transform`·`will-change`를 제거**해 합성 레이어
  승격을 풀어야 합니다. 레이어로 올라간 텍스트는 서브픽셀 안티에일리어싱을 잃고 리샘플링되어 흐려집니다.
  `will-change`를 CSS에 상주시키지 말고 페이드 구간에서만 JS로 붙이세요.
- 이동량은 **정수 px로 스냅**(`Math.round`). 소수점 `translateY`는 텍스트를 흐리게 만듭니다.
- 폰 목업에 `rotateX()` 같은 3D 회전을 쓰지 마세요. 화면 전체를 리샘플링해 안쪽 UI 텍스트까지 흐려집니다.
  정수 `translateY`만 사용합니다.
- `opacity:0`인 스텝은 `visibility:hidden`으로 빼서 유령 텍스트 겹침을 없앱니다.
- 900px 이하와 `prefers-reduced-motion: reduce`에서는 sticky를 해제하고 3단계를 **정적으로 쌓아**
  전부 불투명하게 보여줍니다(인라인 스타일 초기화 포함).

## 프로토타입 규격

372px 폭 폰 셸(라운드 52px, 이중 그림자 + inset 하이라이트) 안에 348×764 화면.
`--ps` 스케일 변수로 뷰포트 폭·높이에 따라 0.72~1.0까지 축소.

- **하단 탭바 3개**: 홈 / 단지 / 내 정보. `role="tablist"` + `aria-selected` 갱신.
- **홈**: 앱 헤더(단지명·동호수·인증 칩·알림 벨), 공지 히어로 카드, 8개 퀵액션 그리드,
  "이번 주 단지 소식" 피드 2개, 하단에 고정된 액센트 `무엇이든 물어보세요` 버튼.
- **단지**: 공지 3개를 아코디언으로(`aria-expanded` 토글).
- **내 정보**: 세대 정보, 알림 스위치 3개(`role="switch"` + `aria-checked`), 학습된 문서 목록.
- **채팅 오버레이**: 아래에서 올라오는 시트, 뒤 화면은 `scale(.955)` + 살짝 감광.
  질문을 보내면 타이핑 인디케이터 → 답변. 답변은 항상 **① 본문(핵심 수치는 `<b>`)
  ② 근거 칩(문서·조항) ③ 다음 행동 카드(버튼 1개)** 구조. 근거를 못 찾은 답변에는 근거 칩을 붙이지 않고
  관리사무소 안내로 대체합니다.
- **키워드 검색 기반 지식베이스**(LLM 호출 없음, 전부 로컬). 키워드 배열 매칭으로 최고 점수 항목 선택,
  0점이면 미확인 응답. 항목 8개:

| 방문차량·주차 | 방문자 구역 **최대 4시간**, 초과 시 시간당 요금 | 주차 관리 규정 제8조 3항 | 방문차량 등록하기 |
| 층간소음 | 주간 40dB·야간 35dB 초과 반복 시 민원 대상 | 층간소음 관리 규정 제12조 | 층간소음 민원 접수하기 |
| 관리비 연체 | 30일 초과 시 연 12% 이내 가산금, 3개월 체납 시 단전·단수 절차 | 관리규약 제5조 2항 | — |

| 커뮤니티 시설 | 헬스장 05:30–23:00, 수영장 06:00–21:00, 독서실 24시간, 카페 09:00–18:00 | 커뮤니티 시설 운영 지침 | — |

| 스마트홈 | 인증 후 조명·난방·환기 제어, 별도 계정 불필요 | 스마트홈 이용 안내 | — |

- **신청 오버레이**: 방문차량 등록 / 민원 접수 / 전자투표 3종. 각각 입력 필드 2~3개 + 제출 버튼 하나.
  제출하면 체크 마크 완료 화면으로 교체.
- **세대 인증 오버레이**: 동·호수 + 연락처. 인증 전에는 신청 액션을 누르면 인증 화면이 먼저 열리고,
  인증 후 헤더 칩이 `인증 완료`로 바뀝니다.
- `Esc`로 열린 오버레이 닫기, 폰 안에서만 스크롤이 갇히게(`overflow` 관리), 스크롤바 숨김.

## 품질 기준

- 모든 인터랙티브 요소 최소 44px 터치 타깃, `:focus-visible` 링은 `--accent-deep` 2px + offset 3px.
- 마우스 hover와 `:active` 상태를 전부 정의(누를 때 `scale(.96~.985)`).
- `prefers-reduced-motion: reduce`에서 스크롤 연동 모션·패럴랙스·펄스를 전부 정지.
- 등장 애니메이션은 `IntersectionObserver` 한 개로 처리하고 한 번 보인 요소는 `unobserve`.
- 브레이크포인트: 1180 / 900 / 640 / 420px + `max-height` 900 / 780px(폰 축소).
- 콘솔 에러 0, 레이아웃 시프트·가로 스크롤 없음.
