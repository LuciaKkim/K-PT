Why this, now

관리규정, 관리비, 공지사항 — 아파트 생활에 필요한 정보는 많지만, 문서는 복잡하고 필요한 조항을 직접 찾아야 합니다.

관리사무소에서는 규정 안내, 공지 작성, 시설 민원 처리 같은 반복 업무가 끊이지 않습니다.

정보는 흩어져 있고, 질문은 창구에 몰리고, 처리는 목록 밖으로 사라집니다.

— 찾고, 묻고, 다시 안내하는 구조.

01 — SERVICE

규정 챗봇이 아니라 관리 서비스

관리규정 + 관리비 + 공지 + 긴급 알림 + 시설 민원을 하나의 아파트 관리 서비스로 묶습니다.

02 — KNOWLEDGE

규정을 공통 지식으로

RAG는 독립하되, 입주민 질문뿐 아니라 관리비 분석·민원 처리에도 같은 근거를 붙일 수 있습니다.

03 — TWO SIDES

입주민과 관리자 양방향

관리자는 공지·알림·민원을 내리고, 입주민은 규정·관리비·접수로 올립니다. 정보 제공과 업무가 한 흐름입니다.

04 — SPLIT

RAG와 일반 서비스의 분리

S3 · API Gateway · Lambda · Bedrock / EC2 · Spring Boot · PostgreSQL. 생성과 트랜잭션의 책임을 나눕니다.
